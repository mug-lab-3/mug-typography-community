# Mug Typography — ギャラリー

[English](README.en.md)

[Mug Typography スクリプティングシミュレータ](https://mug-lab-3.github.io/mug-typography-docs/simulator/)のユーザーが作った作品を集めた場所です。ここに公開された作品は、シミュレータのサンプルブラウザの **gallery** タブに表示されます。

## 作品を登録する

1. シミュレータでアニメーションを作り、スクリプトの `-- @title` に作品名を書きます。
2. **Record** を押して録画します。書き出された `.webm` には Lua のソースが埋め込まれるので、スクリプトを別途貼り付ける必要はありません。
3. サムネイルを撮影します。プレビュー上部のカメラボタンを押すと、**そのとき表示しているフレーム**がカード用の静止画として保存されます。見せたい場面を表示した状態で押してください。
4. [新規登録リクエスト](../../issues/new?template=gallery-submission.yml)を開き、**録画（`.webm`）とサムネイル画像**の2つを添付します。

作品名はスクリプトの `-- @title` から決まります。後で更新・削除するときにこの名前で対象を指定するので、覚えておいてください。

公開前にファイルを差し替えたい場合は、**Issue 本文を編集**して該当の欄に貼り直してください。コメントに添付したファイルは読み取られません。

## 作品を更新・削除する

公開済みの Issue を編集するのではなく、新しく Issue を立ててください。

- [作品を更新する](../../issues/new?template=gallery-update.yml) — 録画・サムネイル・スクリプトをその場で差し替えます。ギャラリー上の位置はそのままです。
- [作品を削除する](../../issues/new?template=gallery-removal.yml) — ギャラリーから取り下げます。添付は不要です。

どちらも **GitHub ユーザー名と作品名**で対象を特定するため、Issue フォームの Title には公開済みの作品名を入力してください。触れるのは自分の作品だけです。公開した作品はすべて `gallery/<あなたのユーザー名>/` の下に置かれ、このパスは Issue を立てた人から決まります。

## 作品の要件

以下はすべて自動検証され、1つでも満たさない場合は Issue にコメントで指摘されます。不足はまとめて報告されるので、一度に直せます。

### 録画（`.webm`）

| 項目 | 要件 |
| --- | --- |
| 形式 | WebM |
| ファイルサイズ | 8 MB 以下 |
| 解像度 | 1280x720 以下 |
| 長さ | 15 秒以下 |
| スクリプト | Lua ソースが埋め込まれていること |

シミュレータの **Record** で書き出せば、埋め込みも解像度も自動的に条件を満たします（デフォルトのキャンバスサイズが 1280x720 のため）。他のツールで作った動画は、スクリプトが埋め込まれていないため受け付けられません。

### サムネイル

| 項目 | 要件 |
| --- | --- |
| 形式 | WebP / PNG / JPEG |
| ファイルサイズ | 500 KB 以下 |
| 解像度 | 1280x720 以下 |

プレビュー上部のカメラボタンで保存すれば条件を満たします。

### スクリプトのヘッダ

録画から取り出したスクリプトの先頭コメントを読み取ります。

| ディレクティブ | 要否 | 用途 |
| --- | --- | --- |
| `-- @title` | **必須** | 作品名。カードの見出しになり、保存先ディレクトリ名も決まります |
| `-- @author` | 任意 | カードの作者名。未指定なら GitHub ユーザー名が使われます |
| `-- @version` | 任意 | カードに表示されるバージョン |
| `-- @api_level` | 任意 | カードに表示される対象 API レベル |
| `--[[ @description ]]` | 任意 | カードの説明文。未指定なら Issue フォームの Description が使われます |

`-- @title` が無い、または値が空の場合は登録できません。シミュレータの New Script はこれらを最初から含んだ雛形を出力するので、通常は書き換えるだけです。

### 添付方法

- ファイルは **Issue 本文の該当欄**にドラッグして添付してください。コメントに添付したファイルは読み取られません。
- 添付は GitHub にアップロードされたものに限ります。外部URLは受け付けません。

### 更新・削除の場合

- Issue フォームの Title に、**公開済みの作品名**（＝そのときの `-- @title`）を入力してください。これで対象を特定します。
- 更新では、添付するスクリプトの `-- @title` も同じである必要があります。異なる場合はエラーになります（別作品として二重に登録されるのを防ぐため）。作品名を変えたい場合は、削除してから新規登録してください。

## 公開までの流れ

投稿は人の手でレビューされます。Issue を立てただけでは何も自動実行されません。

1. メンテナが `gallery:check` ラベルを付けます。ワークフローが添付ファイルを上記の制限に照らして検証し、埋め込まれたスクリプトを取り出して、結果をコメントします。
2. メンテナが `approved` ラベルを付けます。ワークフローが再検証し、`gallery/` 以下に変更を適用して `catalog.json` を再生成し、プルリクエストを作成します。
3. そのプルリクエストがマージされると公開されます。シミュレータは `catalog.json` を実行時に取得するため、再デプロイは不要です。

## リポジトリの構成

- `gallery/<ユーザー名>/<タイトル>/` — 公開作品ごとのディレクトリ。`script.lua`、`preview.webm`、`thumbnail.*`、`metadata.json` を格納します。
- `catalog.json` — `scripts/build-catalog.mjs` が `gallery/` から生成する索引です。スクリプト本体は持たず、その場所だけを記録します。シミュレータが直接取得するため、手で編集しないでください。
- `scripts/` — ワークフローが実行する検証・カタログ生成ツール。

## ライセンス

投稿することで、そのスクリプトがあなた自身の著作物であること、および本プロジェクトの一部として配布されることに同意したものとみなされます。
